# Amazon S3

Amazon Simple Storage Service: almacenamiento de objetos, el disco duro de los datos en AWS.

---

# Qué es S3

- Servicio de **almacenamiento de objetos** con una interfaz web sencilla para guardar y recuperar cualquier cantidad de datos.
- Durabilidad diseñada del **99,999999999 %** y disponibilidad del 99,99 % al año en la clase Standard.
- Datos replicados en al menos tres zonas de disponibilidad (salvo las clases de una sola zona): aguanta la pérdida simultánea de datos en dos ubicaciones.
- Objetos de hasta **50 TB**.
- **Consistencia fuerte**: en cuanto escribes un objeto, cualquier lectura posterior ve la versión nueva.
- Todos los objetos se **cifran** por defecto.
- Los buckets bloquean el **acceso público** por defecto.

---

# Cómo trabajar con S3

Las mismas operaciones se pueden hacer desde:

- La **consola web** de AWS.
- La **CLI** (`aws s3 ...`).
- La extensión **AWS Toolkit** de Visual Studio Code.
- **Python** con boto3.
- **Pandas**, que lee y escribe ficheros directamente con su ruta `s3://`.

# Cómo se llega a S3

![Acceso a S3 por Internet o por un endpoint de puerta de enlace](assets/img/11-s3/s3.png)

S3 es un servicio público: se accede por Internet o, desde una VPC, de forma privada con un **endpoint de puerta de enlace**.

# Buckets

- Un bucket es el **contenedor** de objetos en S3. Todo objeto está dentro de un bucket.
- El nombre del bucket es **único en todo AWS**, no solo en tu cuenta.
- Cada bucket vive en una región.
- Puedes conceder o denegar a otras personas o servicios permiso para subir o descargar datos de tu bucket (políticas de IAM y del bucket).

Por ejemplo, el objeto `market/2018/datos.csv` del bucket `miax-{{alias}}-datos` en `{{region}}` tiene la URL:

```text
https://miax-{{alias}}-datos.s3.{{region}}.amazonaws.com/market/2018/datos.csv
        └── bucket ────────┘                             └──── clave ─────────┘
```

---

# Objetos

- Los objetos son las entidades que se almacenan en S3.
- Un objeto se compone de **datos** y **metadatos**.
- Los datos son opacos para S3: no le importa lo que contienen.
- Los metadatos son pares nombre-valor que describen el objeto:
  - Del sistema: fecha de última modificación, tamaño, `Content-Type`…
  - Personalizados: los defines tú al subir el objeto (`x-amz-meta-...`).

---

# Claves

- La **clave** es el identificador único de un objeto dentro de un bucket. Cada objeto tiene exactamente una.
- **Bucket + clave + versión** identifican de forma única cada objeto: S3 es, en el fondo, un mapa de «bucket + clave + versión» al objeto.
- Las «carpetas» no existen: `market/2018/` es solo parte de la clave, un **prefijo**. La consola lo muestra como carpetas por comodidad.

| Concepto | Descripción |
|---|---|
| **Bucket** | Contenedor con nombre único global, ubicado en una región |
| **Objeto** | Datos más metadatos |
| **Clave** | Identificador del objeto dentro del bucket |
| **Versión** | Permite conservar el historial de un objeto (si activas el versionado) |

---

# Regiones

- Eliges la región de AWS donde se guarda cada bucket.
- La elección optimiza la **latencia**, minimiza **costes** o cumple **requisitos legales** (por ejemplo, datos en la UE).
- Los objetos de una región **nunca la abandonan** salvo que los copies o repliques expresamente a otra.

# Clases de almacenamiento

Cada clase está pensada para un patrón de uso distinto: cuanto menos accedes a los datos, menos pagas por guardarlos y más pagas (o esperas) por leerlos.

| Clase | Para |
|---|---|
| **Standard** | Uso general, acceso frecuente |
| **Express One Zone** | Latencia muy baja, una sola zona |
| **Intelligent-Tiering** | Patrón de acceso desconocido o cambiante |
| **Standard-IA / One Zone-IA** | Datos de larga duración con acceso poco frecuente |
| **Glacier Instant / Flexible / Deep Archive** | Archivado a largo plazo |

Las reglas de **ciclo de vida** mueven o borran objetos automáticamente. Precios: [S3 pricing](https://aws.amazon.com/es/s3/pricing/).

# CLI: buckets y listados

Crear un bucket:

```bash
aws s3 mb <target> [--options]
aws s3 mb s3://miax-{{alias}}-datos --region {{region}}
```

Listar buckets y objetos:

```bash
aws s3 ls <target> [--options]

aws s3 ls                                     # todos tus buckets
aws s3 ls s3://miax-{{alias}}-datos            # objetos del bucket
aws s3 ls s3://miax-{{alias}}-datos/market/    # objetos con un prefijo
```

Eliminar un bucket (solo si está vacío; `--force` lo vacía antes):

```bash
aws s3 rb <target> [--options]
aws s3 rb s3://miax-{{alias}}-datos
```

---

# CLI: copiar y mover

Copiar (`cp`) y mover (`mv`) usan la misma sintaxis. Origen y destino pueden ser locales o de S3:

```bash
aws s3 cp <source> <target> [--options]
aws s3 mv <source> <target> [--options]
```

```bash
aws s3 cp fichero.txt s3://miax-{{alias}}-datos/            # local → bucket
aws s3 cp s3://miax-{{alias}}-datos/fichero.txt ./          # bucket → local
aws s3 cp s3://miax-{{alias}}-datos/market/ s3://otro-bucket/ --recursive

aws s3 mv fichero.txt s3://miax-{{alias}}-datos/            # sube y borra el local
aws s3 mv s3://miax-{{alias}}-datos/fichero.txt ./          # baja y borra el remoto
aws s3 mv s3://miax-{{alias}}-datos/a.txt s3://miax-{{alias}}-datos/b.txt
```

Sincronizar una carpeta (solo copia lo que ha cambiado):

```bash
aws s3 sync ./datos s3://miax-{{alias}}-datos/datos/
```

---

# CLI: borrar y `--recursive`

```bash
aws s3 rm <target> [--options]

aws s3 rm s3://miax-{{alias}}-datos/fichero.txt
aws s3 rm s3://miax-{{alias}}-datos/market/ --recursive
```

Con `--recursive` el comando se aplica a **todos los objetos con ese prefijo** (o a todos los ficheros de la carpeta local). Sirve en `cp`, `mv` y `rm`.

Referencia: [comandos `aws s3` de la CLI](https://docs.aws.amazon.com/cli/latest/userguide/cli-services-s3-commands.html).

# Desde Python: boto3

```python
import boto3

s3 = boto3.client("s3", region_name="{{region}}")
bucket = "miax-{{alias}}-datos"

# Crear un bucket
s3.create_bucket(
    Bucket=bucket,
    CreateBucketConfiguration={"LocationConstraint": "{{region}}"},
)

# Subir y descargar un fichero
s3.upload_file("market_data.txt", bucket, "market_data.txt")
s3.download_file(bucket, "market_data.txt", "/tmp/market_data.txt")

# Listar objetos
respuesta = s3.list_objects_v2(Bucket=bucket)
for objeto in respuesta.get("Contents", []):
    print(objeto["Key"], objeto["Size"])
```

`LocationConstraint` es obligatorio salvo en `us-east-1`. `list_objects_v2` devuelve hasta 1.000 claves: usa un paginador si hay más.

# boto3: ficheros abiertos y recursos

Subir un fichero ya abierto (o cualquier objeto tipo fichero en binario):

```python
with open("market_data.txt", "rb") as f:
    s3.upload_fileobj(f, bucket, "market_data.txt")
```

boto3 tiene dos interfaces: el **cliente** (`boto3.client`), que refleja la API una a una, y el **recurso** (`boto3.resource`), más orientado a objetos:

```python
s3r = boto3.resource("s3")
s3r.Bucket(bucket).download_file("market_data.txt", "/tmp/market_data.txt")
```

Documentación: [ejemplos de S3 con boto3](https://boto3.amazonaws.com/v1/documentation/api/latest/guide/s3-examples.html). Notebook completo: [boto3_s3_example.ipynb](ejemplos/s3/boto3_s3_example.ipynb).

# Credenciales en Python

boto3 y pandas buscan las credenciales solos, en este orden:

1. Parámetros explícitos en el código.
2. **Variables de entorno**: `AWS_ACCESS_KEY_ID`, `AWS_SECRET_ACCESS_KEY` y, si son temporales, `AWS_SESSION_TOKEN`.
3. Los ficheros **`~/.aws/config`** y **`~/.aws/credentials`**, que crean `aws login` o `aws configure`.
4. El **rol de IAM** de la instancia EC2, la función Lambda o el contenedor.

Si la CLI funciona en tu máquina, boto3 y pandas también, sin hacer nada más.

Orden recomendado:

- **En AWS**: un rol de IAM asociado a la instancia o función. No hay que configurar nada.
- **En tu ordenador**: `aws login`.

---

# Claves en el código: no

Así se pasan las claves directamente, y es lo que **no** debes hacer:

```python
session = boto3.Session(
    aws_access_key_id="AKIA...",
    aws_secret_access_key="...",
)
s3 = session.client("s3")
```

::: aviso Evita las claves en el código
Las claves en el código acaban en Git, en capturas y en logs. Si tienes que usar claves, ponlas en variables de entorno o en `~/.aws/credentials`, nunca en el programa.
:::

# Desde pandas

Pandas usa la librería `s3fs` para leer y escribir rutas `s3://`:

```bash
pip install pandas s3fs
```

```python
import pandas as pd

bucket = "miax-{{alias}}-datos"
df = pd.read_csv(f"s3://{bucket}/market_data.txt", sep=";")
df = df.loc[:, ["FECHA", "HORA", "VALOR", "PRECIO", "VOLUMEN"]]
df.to_csv(f"s3://{bucket}/market_data_mod.csv", index=False)
```

Las credenciales se buscan igual que en boto3.

# pandas con credenciales explícitas

Si necesitas pasar credenciales temporales concretas, usa `storage_options`:

```python
import os

opciones = {
    "key": os.environ["AWS_ACCESS_KEY_ID"],
    "secret": os.environ["AWS_SECRET_ACCESS_KEY"],
    "token": os.environ["AWS_SESSION_TOKEN"],
}

df = pd.read_csv(f"s3://{bucket}/market_data.txt", sep=";", storage_options=opciones)

df.to_csv(f"s3://{bucket}/market_data_mod.csv", index=False, storage_options=opciones)
```
